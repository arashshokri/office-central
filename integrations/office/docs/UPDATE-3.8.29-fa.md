# رفع محدودیت شروع بروزرسانی در Office 3.8.29

Office نسخهٔ `3.8.23` برای بررسی نسخه، شروع نصب و پیگیری وضعیت از محدودکننده‌های عددی Laravel استفاده می‌کند. این مسیرها برای کاربر واردشده یک شمارندهٔ مشترک دارند؛ پیگیری وضعیت می‌تواند سهمیهٔ سه‌درخواستِ شروع نصب را مصرف کند. تعویض helper، کد PHP و JavaScript داخل ایمیج Office قدیمی را تغییر نمی‌دهد.

در نسخهٔ `3.8.29` شمارنده‌های این عملیات مستقل هستند. شروع نصب دو محدودیت جدا دارد: حداکثر ۶۰ درخواست در دقیقه و حداکثر ۱۰ عملیات جدید پذیرفته‌شده در دقیقه برای هر مدیر. خطای اعتبارسنجی یا پاسخ ناموفق helper سهمیهٔ عملیات پذیرفته‌شده را مصرف نمی‌کند. پاسخ‌های مربوط به یک شناسهٔ عملیات یک بار شمرده می‌شوند؛ عملیات در حال اجرا بدون بررسی دوبارهٔ مرکز برگردانده می‌شود. محدودیت تعداد درخواست‌ها همچنان اعمال می‌شود و قفل اجرای helper مانع نصب هم‌زمان است.

مرورگر زمان `Retry-After` را رعایت می‌کند، دکمهٔ نصب و تأیید را در این مدت می‌بندد و شمارش معکوس نشان می‌دهد. پس از خطای شروع، وضعیت عملیات خوانده می‌شود؛ درخواست نصب خودکار تکرار نمی‌شود. اگر عملیاتی آغاز نشده باشد، پس از پایان انتظار مدیر باید دوباره نسخه را تأیید کند.

## رساندن Office قدیمی به نسخهٔ اصلاح‌شده

۱. روی سرور Central:

```bash
cd /opt/office-central
sudo bash centralctl.sh update v1.4.0-rc.20
```

۲. در Central نسخهٔ `v3.8.29` را از مخزن Office دریافت و منتشر کنید. سپس در لایسنس همین مشتری، نسخهٔ مجاز بروزرسانی را روی `3.8.29` ذخیره کنید. دریافت نسخه به‌تنهایی مجوز مشتری را تغییر نمی‌دهد.

۳. روی سرور Office، helper را تازه کنید؛ کد نصب مصرف‌شده را دوباره وارد نکنید:

```bash
cd /opt/office
curl --fail --proto '=https' --tlsv1.2 https://update.ponet.ir/agent/install.sh -o office-install.sh
sudo bash office-install.sh
sudo office-agent update --expected-version 3.8.29
```

فرمان آخر از سوکت محلی helper استفاده می‌کند و از محدودکنندهٔ وب نسخهٔ قدیمی عبور می‌کند. فقط نسخهٔ مشخص‌شده، در صورت مجازبودن برای لایسنس و سخت‌افزار فعلی، قابل نصب است. اگر نسخهٔ تخصیص‌یافته تغییر کرده باشد، شروع نصب رد می‌شود. این فرمان پاسخ آغاز عملیات را می‌دهد؛ دریافت پاسخ `running` به معنای تکمیل نصب نیست.

۴. پیگیری پیشرفت بدون آغاز نصب دوباره:

```bash
sudo office-agent update-status
sudo journalctl -u office-agent -n 50 --no-pager
```

`status: success` و `progress: 100` فقط پس از سلامت برنامه و ثبت رسید نصب در Central اعلام می‌شوند. پس از تکمیل، صفحهٔ Office را تازه کنید تا JavaScript جدید بارگذاری شود؛ بروزرسانی‌های بعدی از همان صفحهٔ بروزرسانی سامانه قابل انجام‌اند. هویت نصب، لایسنس، اطلاعات مشتری و دیتابیس حفظ می‌شوند و پیش از اعمال تغییرات نصب، بکاپ تهیه می‌شود.

اگر هنوز پاسخ 429 دارید، مسیر درخواست و مقدار `Retry-After` در Network مرورگر مشخص می‌کند محدودیت متعلق به Office است یا سرویس بالادستی. وضعیت و لاگ helper علت خطای نصب را نشان می‌دهند؛ حذف دیتابیس، پاک‌کردن Redis یا صدور مجدد لایسنس راه رفع محدودیت درخواست نیست.
