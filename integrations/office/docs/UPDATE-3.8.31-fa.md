# نصب وبی و پنجرهٔ پیشرفت بروزرسانی — Office 3.8.31

Central: `v1.4.0-rc.22` — Office: `v3.8.31`.

## بروزرسانی نصب موجود

در سرور Central:

```bash
cd /opt/office-central
sudo bash centralctl.sh update v1.4.0-rc.22
```

دریافت نسخهٔ Office 3.8.31 از مخزن، انتشار آن و انتخاب آن در «نسخهٔ مجاز بروزرسانی» لایسنس مشتری لازم است. پس از این بروزرسانی، پنل Office پنجرهٔ تأیید و پیشرفت نصب را در یک پنجره نمایش می‌دهد. UI نسخه‌های قدیمی با نصب فایل هلپر به‌تنهایی تغییر نمی‌کند.

برای تازه‌کردن هلپر روی نصب موجود:

```bash
(
  set -e
  office_download_dir=$(mktemp -d)
  curl --fail --proto '=https' --tlsv1.2 https://update.ponet.ir/agent/install.sh -o "$office_download_dir/office-install.sh"
  sudo bash "$office_download_dir/office-install.sh"
)
```

سپس در Office «چک کردن بروزرسانی» و «بروزرسانی سامانه» را بزنید. نسخهٔ فعلی و مقصد در پنجره نشان داده می‌شوند؛ نصب فقط با تأیید شما شروع می‌شود. اگر نسخهٔ قبلی به آغاز نصب از CLI نیاز داشت:

```bash
sudo office-agent update --expected-version 3.8.31
sudo office-agent update-status
```

## نصب روی سرور جدید مشتری

۱. در Central لایسنس «نصب روی سرور جدید» صادر کنید؛ نسخهٔ منتشرشدهٔ Office، آدرس HTTPS پنل و تنظیمات پیش‌فرض آن را تعیین کنید. کد یکبارمصرف تنها پس از تأیید سلامت Office و دریافت رسید تکمیل نصب مصرف می‌شود.

۲. روی سرور Linux تازه، curl، python3 و CA certificates موجود باشند. `SERVER_IP` را با IP یا نام میزبان قابل دسترس مشتری جایگزین کنید:

```bash
(
  set -e
  office_download_dir=$(mktemp -d)
  curl --fail --proto '=https' --tlsv1.2 https://update.ponet.ir/agent/install.sh -o "$office_download_dir/office-install.sh"
  sudo bash "$office_download_dir/office-install.sh" --setup-host SERVER_IP
)
```

پس از آماده شدن پیش‌نیازهای Docker، دستور لینک خصوصی `https://SERVER_IP:8443/#...` می‌دهد. پورت TCP 8443 باید برای مشتری قابل دسترس باشد. هلپر فایروال را تغییر نمی‌دهد. لینک را خصوصی نگه دارید؛ کل لینک شامل بخش پس از `#` را باز کنید.

۳. راه‌انداز با HTTPS اجرا می‌شود. اگر گواهی معتبر ندارید، هلپر گواهی موقت می‌سازد و اثر انگشت SHA-256 آن را در SSH نشان می‌دهد؛ قبل از قبول گواهی در مرورگر اثر انگشت را بررسی کنید. برای نمایش بدون هشدار مرورگر، نام میزبان و گواهی معتبر همان میزبان را بدهید:

```bash
sudo bash office-install.sh --setup-host setup.customer.ir \
  --setup-cert /etc/letsencrypt/live/setup.customer.ir/fullchain.pem \
  --setup-key /etc/letsencrypt/live/setup.customer.ir/privkey.pem
```

گواهی و کلید در مسیر خصوصی هلپر کپی می‌شوند و فایل اصلی تغییر نمی‌کند. پورت راه‌انداز با `--setup-port` و IP گوش‌دادن با `--setup-bind` قابل تعیین است.

۴. در وب: لایسنس ← تنظیمات اتصال و حساب مدیر ← تأیید نصب. نام کاربری ورود به Office همان ایمیل مدیر است؛ رمز حداقل ۱۲ کاراکتر را خود مشتری انتخاب می‌کند. آدرس پنل از لایسنس گرفته می‌شود و در راه‌انداز قابل تغییر نیست. در صورت استفاده از Nginx Proxy Manager روی همین سرور، شبکهٔ موجود Docker را وارد کنید؛ مقصد Office `office-web:8080` است. آدرس دامنهٔ پنل، SSL و پروکسی باید توسط مدیر سرور تنظیم شوند؛ راه‌انداز به پنل NPM وارد نمی‌شود.

۵. دریافت بسته، ساخت یا بارگذاری ایمیج‌ها، دیتابیس، حساب مدیر، سرویس‌ها، سلامت و رسید فعال‌سازی داخل پنجره پیگیری می‌شوند. پیشرفت براساس کار انجام‌شده است؛ ساخت یک مرحله ممکن است چند دقیقه درصد ثابتی داشته باشد. فقط تکمیل واقعی ۱۰۰٪ می‌شود. پایان نصب آدرس ورود و ایمیل مدیر نمایش داده می‌شوند؛ رمز مجدداً نمایش داده نمی‌شود.

بستن مرورگر نصب را متوقف نمی‌کند. همان لینک و همان تب وضعیت را بازیابی می‌کنند؛ لینک کامل اولیه را برای مرورگر دیگر استفاده کنید. خطا همراه مرحله نمایش داده می‌شود؛ ادامهٔ نصب به تأیید دوباره نیاز دارد. هویت نصب، بستهٔ دانلودشده، حساب مدیر و اطلاعات دیتابیس در ادامه حفظ می‌شوند. لایسنس مصرف‌شده دوباره ارسال نمی‌شود.

لینک نصب ۲۴ ساعت اعتبار دارد؛ سرویس وب ۱۵ دقیقه پس از تکمیل بسته می‌شود. سرویس اصلی `office-agent` فعال باقی می‌ماند. برای خطاهای راه‌انداز:

```bash
sudo journalctl -u office-installer -n 80 --no-pager
sudo office-agent status
```

این راه‌انداز مخصوص نصب جدید یا ادامهٔ همان نصب است. برای Office دارای اطلاعات مشتری از مسیر اتصال و بروزرسانی استفاده کنید. هیچ فرمان حذف volume، پاک‌سازی دیتابیس یا نصب دوبارهٔ Office موجود اجرا نمی‌شود.
